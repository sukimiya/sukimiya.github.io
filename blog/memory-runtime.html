Memory Runtime：从 KV Cache 到长期记忆的分层 AI Memory 架构

今天的大语言模型存在一个很容易被误解的概念：

Context 并不等于 Memory。

把过去几十万甚至几百万 Token 全部重新放进 Context，并不是一个真正可扩展的长期记忆方案。

对于长期运行的 Personal AI、Agent 和具身机器人，我们需要的不是一个无限增长的 Context Window，而是一套真正的：

Memory Runtime

它负责决定：

什么应该立即记住，什么值得长期保存，什么可以压缩，以及需要的时候如何重新找到原始信息。

1. 为什么 KV Cache 不能承担长期记忆

Transformer 在生成 Token 时，会保存 Attention 的 Key / Value。

这就是 KV Cache。

KV Cache 的作用是：

避免每生成一个新 Token，都重新计算此前所有 Token。

因此它本质上属于：

Working Memory。

而不是 Long-Term Memory。

随着 Context 增长：

Token
  ↓
更多 Token
  ↓
更多 K/V
  ↓
KV Cache 增长
  ↓
Memory Pressure

如果同时存在多个 Agent：

Agent A → KV
Agent B → KV
Agent C → KV
Agent D → KV

问题会更加严重。

因此一个长期运行的 AI 不能依赖：

无限 Context
+
无限 KV Cache

实现记忆。

2. 四层 Memory Architecture

一个更合理的设计可以分成四层：

                 MEMORY RUNTIME

                       │
                       ▼

                L0 — Hot Memory
                   KV Cache
                       │
                       ▼
              L1 — Salient Memory
                 关键语义记忆
                       │
                       ▼
              L2 — Indexed Memory
                目录式压缩记忆
                       │
                       ▼
              L3 — Archive Memory
                  全量原始记录

四层分别回答四个问题：

L0：我现在正在想什么？

L1：什么事情值得记住？

L2：过去的信息在哪里？

L3：当时究竟发生了什么？

3. L0：Hot KV Cache

L0 是真正意义上的 Transformer KV Cache。

它保存：

当前 Prompt
最近对话
当前推理过程
当前任务状态

这一层要求：

最快速度、最低延迟。

例如：

0 ~ 8K Tokens

可以直接保留完整 Context。

随着 Context 老化：

Current Context
      │
      ▼
Sliding Window
      │
 ┌────┴────┐
 │         │
Keep     Aging
           │
           ▼
       Compress

旧信息逐渐退出 Hot KV。

但：

退出 KV Cache ≠ 被遗忘。

4. L1：Salient Memory

L1 保存的不是最近发生的事情。

而是：

重要的事情。

例如一段两小时视频中：

普通镜头
普通对话
普通镜头
      │
      ├── ★ 主角关键对话
      │
      ├── ★ 重要事件
      │
      └── ★ 人物关系变化

只有真正重要的信息进入 L1。

同样，一篇 100 页论文可能只有：

Figure 4

真正决定整篇论文的架构。

那么这张图就应该成为一个 Salient Memory Object。

5. L1 保存的是 Semantic Object

例如：

Memory Object

Type:
Architecture Diagram

Meaning:
Reaction Path 与 Cognitive Path
并行运行。

Source:
architecture.pdf

Location:
Page 17 / Figure 4

Related:
→ Robot Architecture
→ Cognitive Runtime
→ Action System

Importance:
0.93

Retrievable:
YES

对于视频：

Type:
Dialogue Event

Participants:
Person A
Person B

Timestamp:
01:24:17

Meaning:
人物第一次明确表达某个关键观点。

Source:
video_001

Importance:
0.91

这里保存的核心不是原始数据。

而是：

Meaning + Source Pointer。

也就是：

我记得发生过什么，而且知道去哪里找证据。

6. L2：Hierarchical Indexed Memory

L2 不应该只是普通 Summary。

它应该像一本书的：

目录。

例如：

Memory Index
│
├── Local LLM
│
│   ├── Quantization
│
│   ├── KV Cache
│
│   └── Unified Memory
│
├── Robot Architecture
│
│   ├── Reaction Path
│
│   ├── Cognitive Path
│
│   └── Memory Runtime
│
└── MoE
    │
    ├── Expert Routing
    └── Memory Scheduling

模型首先读取一个非常小的目录。

例如：

2K Tokens

然后发现：

这个问题可能与 KV Cache 有关。

再向下读取：

Memory Index
     ↓
Local LLM
     ↓
KV Cache
     ↓
OOM Discussion
     ↓
Original Conversation

这是一种：

Progressive Retrieval

而不是一次加载全部记忆。

7. 压缩不能破坏原始信息

传统 Summary：

100K Tokens
     ↓
LLM Summary
     ↓
2K Tokens

存在一个严重问题：

摘要过程中丢失的信息以后可能重新变得重要。

因此 Memory Runtime 应该采用：

Recoverable Compression

也就是：

Original Memory
       │
       ├── Summary
       ├── Topic Index
       ├── Entity Index
       ├── Timeline
       ├── Event Index
       ├── Decision Index
       └── Source Pointer

Summary 可以有损。

但是：

Source Pointer 不能丢。

这样：

Summary
   ↓
发现相关信息
   ↓
Source Pointer
   ↓
Original Chunk

就可以重新恢复完整内容。

因此一个非常重要的原则是：

Compression should reduce active context, not destroy source information.

8. L3：Full Archive

L3 是完整的长期存储。

它可以保存：

Conversation
Documents
PDF
Images
Video
Audio
Sensor Data
Robot Logs
Source Code
Project Files

这一层可以使用非常便宜的大容量存储。

例如：

NVMe SSD
NAS
Local Storage
Encrypted Archive

9. RAG 不是 Memory

这里必须区分：

Memory

和：

Memory Access Method

真正的 Memory 应该是原始数据：

Raw Conversation
Raw Document
Raw Video
Raw Image

而：

Vector Database
Embedding
Full-text Search
Graph Search
Timeline Index

应该只是：

访问 Memory 的索引。

因此：

             Raw Memory
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼

    Vector     Graph     Full Text
     Index     Index       Index

这样即使未来更换 Embedding Model：

Embedding V1
     ↓
Embedding V2

只需要重新建立索引。

原始记忆仍然完整存在。

10. Memory Consolidation

Memory Runtime 还需要一个非常重要的后台过程：

Consolidation

因为不是所有事情都值得进入 L1。

系统需要判断：

Importance
Novelty
Goal Relevance
Repeated Occurrence
Social Relevance
Causal Significance
User Explicit Importance
Future Utility

例如机器人看到：

桌上有一个蓝色杯子。

可能只是短期视觉状态。

但如果用户说：

这个杯子是我父亲留下来的，
不要把它丢掉。

它就应该发生：

Visual State
     ↓
Semantic Understanding
     ↓
Importance ↑
     ↓
L1 Salient Memory

11. Memory Promotion 与 Demotion

因此 Memory 不应该只是：

写入
读取

而应该存在生命周期：

                    New Information
                           │
                           ▼
                          L0
                           │
                  Importance Check
                           │
             ┌─────────────┴─────────────┐
             │                           │
          Important                    Normal
             │                           │
             ▼                           ▼
            L1                          L2
                                         │
                                      Aging
                                         │
                                         ▼
                                        L3

与此同时：

L3
 │
 │ Retrieval
 ▼
L2
 │
 │ Relevant
 ▼
L1
 │
 │ Current Task
 ▼
L0

所以 Memory 是可以：

升温和降温的。

12. 最终 Memory Runtime

完整架构可以表示为：

                        LLM / VLM
                            │
                            ▼
                    Memory Controller
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
        ▼                   ▼                   ▼

    Attention           Retrieval          Consolidation
        │                   │                   │
        ▼                   ▼                   ▼

     L0 Hot             L1 Salient          Memory Judge
     KV Cache              Memory
        │                   │
        └──────────┬────────┘
                   │
                   ▼
             L2 Memory Index
                   │
                   ▼
               L3 Archive

这样一个长期运行的 AI 不需要拥有：

无限 Context Window。

它真正需要的是：

有限但高速的工作记忆 + 重要信息记忆 + 可导航的知识目录 + 完整长期档案。

结论

可以用四句话概括整个 Memory Runtime：

L0 remembers what I am thinking.

L1 remembers what matters.

L2 remembers where knowledge is.

L3 remembers what happened.

中文就是：

L0 记住正在思考什么。

L1 记住什么重要。

L2 记住去哪里找。

L3 保存发生过的一切。

真正的长期 AI Memory，并不是制造一个越来越巨大的 KV Cache。

而是让机器拥有一种类似“记忆组织能力”的机制：

知道什么值得记住，知道什么可以暂时忘记，也知道需要的时候应该去哪里重新找回来。
